# ADR 0005: Latin American neutral by default, accept every dialect when scoring

> **Note (M19e, 2026-10-21):** game-side matters in this record, such as the engine choice and the game's scenes, are now decided in the Vocaterra game repository, not in this one. The text below is unchanged.

- Status: accepted
- Date: 2026-10-20
- Deciders: repository owner and the implementation plan (`implementation-plan.md` section 1, "Default dialect")

## Context

Spanish has no single pronunciation. Distinción (`z` and `c` before `e`/`i` as `θ`) against seseo (`s`), yeísmo against a
distinct `ll`, the sound of `ll` and `y` in Rioplatense speech, and aspirated syllable-final `s` in the Caribbean are all
correct. A reference pronunciation that picks one of them would mark valid speech as wrong. The high-level design lists this
as a risk ("Dialect bias in reference: penalizing valid Latin American speech") and an open question ("Default dialect for NPC
speech, and is it player-selectable?").

Two different things need a dialect:

- the voice the NPCs speak with (the reference the learner hears), and
- the reference the learner is graded against.

## Decision

- **NPC speech uses Latin American neutral:** seseo and yeísmo, `ll` and `y` as `ʝ`, no `s` aspiration
  (`DialectConfig.LatinAmericanNeutral`). `SpeechRequests.Create` phonemizes with it unless the caller passes another
  dialect.
- **Grading accepts all shipped dialects.** `SpanishG2p.PhonemizeAll(text)` returns the distinct realizations for every
  preset in `DialectConfig.AllShipped`, with the default first: Latin American neutral, Castilian standard, Rioplatense,
  Caribbean and Andean (lleísta). The pronunciation scorer aligns the learner's phones against each accepted variant and
  keeps the best one, so a Castilian `θ` is as correct as a Latin American `s`.
- **Word-level answer sets are dialect-aware too.** Answers carry `aliases` (for example `coche`, `carro`, `auto`) and a
  `dialects` list, and a match on an alias counts as correct.
- **Error variants are separate from dialect variants.** Predicted English-speaker errors (`pron.r`, `pron.silent_h`,
  `pron.vowel`, `pron.stress`) are generated by `PredictedErrorVariants` and are never mixed into the accepted set.
- Whether the player can pick their own NPC dialect is not decided here (see consequences).

## Consequences

- No valid regional pronunciation is penalized, which is what the risk table asks for.
- The price is discrimination. The more variants are accepted, the more room a mispronunciation has to land on one of them
  by accident. Variants that are identical in phones and syllables are collapsed, so the cost is only paid where dialects
  really differ.
- Each accepted variant is one more alignment per utterance in the pronunciation scorer. Only the variants of the utterance
  text are aligned, so the cost grows with the number of dialect presets, not with vocabulary.
- Selecting a dialect for NPC speech is a one-parameter change (`SpeechRequests.Create(..., dialect)`), but the shipped
  dialogue and the pre-rendered lines would have to be recorded per dialect. Making the choice available to the player is an
  open product question and is not implemented.
- Distinción in particular is accepted for grading but not spoken by any NPC in v1.
