# Scripted runs: the front-end's regression set

Thirty-two scripted runs of the game that between them pass through every flow `VoxelGame` drives: the walk and the camp, talking and typing,
the first session's three NPCs and the village's (the baker's sale and the fisher's directions, village-plan V09; the market of session 10 and the simple
future in free talk, V09 after phase B), the lessons, the book,
the inventory and crafting panels, the check battery, a whole playtest, the mic check, a saved report, the view over the shoulder, greyscale and
dusk, the interface text size, a spoken line, the sleep at the fire into the next session, a game skipped to a later session (V12c) and, since Y13, the settlement series: day one to the inn's bed, the land bought from the mayor and the camp on it. Run them before a change to the front-end and
after it, and compare what each one wrote (stdout, screenshots, saves, sound logs, the session log). They are the check the tests cannot
give for rendering and input (R16).

## How to run them

Build once, then run each command from the repository root. Every run is a heavy command, so it goes through `scripts/limited.sh` (one at a
time, capped; CLAUDE.md "Machine resources"). A run ends by itself at `--screenshot` once `--frames` have passed and the turns are in.

```bash
PATH="$HOME/.dotnet:$PATH" DOTNET_ROOT="$HOME/.dotnet" DOTNET_NOLOGO=1 scripts/limited.sh dotnet build Vocaterra.sln -warnaserror -m:4
export DISPLAY=:0 VOCATERRA_MODELS_DIR="$HOME/.local/share/vocaterra/models"
GAME=src/Vocaterra.Game/bin/Debug/net10.0/Vocaterra.Game
W=/tmp/vocaterra-run          # one work folder: clear it before each run, then copy it away (see "Comparing" below)
rm -rf "$W" && mkdir -p "$W"
```

Every command below also takes `--session-dir "$W/session"` and, since N01, `--needs off` (the player's needs frozen full, so the runs keep their baselines; `scripts/scripted-runs.sh` adds both), so that the session log, the autosave and the reports land in the work folder.
It is left out of the table for brevity.

`scripts/scripted-runs.sh OUT [name...]` runs them all (or the named ones) this way and keeps each run's folder in `OUT/<name>`;
`python3 -I scripts/compare-runs.py BASE NEW` compares two captures with the masks and the order-only rule below (exit 1 on a difference). Take
the baseline with the same script and the same work folder (`VOCATERRA_RUNS_WORK`) as the capture it is compared with: the work folder's path is
in the output.

## Steps after a teleport (B07b)

In the streamed world a `--teleport` is followed by a hold: the simulation does not run until the world round the new place is resident (the near zone, two columns each way; `docs/game/running.md`, "The streamed world"). The steps after the teleport wait with it: a `--shot` is taken, a `--look` turned and a `--walk-to` begun only once the world is there, so `--teleport 212,256 --look 180,-8 --shot a.png` shows the lake and not the view from the start (it showed the start's before B07b). The hold costs a few frames and no more than a tick of the script's own (the teleport takes its tick); with `--no-settle` the shot is of the near zone (the far land and the rest of the ground follow over the next seconds), without it the frame settles everything first. A bounded world (`--world valley`, the baselines of the table) has no hold: the next step runs in the same tick as before, so those runs compare as they did.
