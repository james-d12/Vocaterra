# QA report: save (inventory and equipment, I-series), 2026-11-19

Branch `feature/inventory`, commit `538a5de1`. Build: the Release binary `src/Vocaterra.Game/bin/Release/net10.0/Vocaterra.Game` (not rebuilt). Seed 42, `--mute --needs off` unless noted, one session folder per run under the QA scratchpad (`qa-save/<run>/`).

Covered: 20 game runs.
- Fresh game saved at once (`r00-fresh`): starting clothes are shirt, trousers and shoes in clothing, 30 slots, no wear.
- Full gear set (`r01-gear`): shirt, trousers, shoes, hat at `--wear hat=240` (worn out), coat, helmet, cuirass, greaves, boots, ring, bracelet, amulet, lantern, sack, `--wear axe=200`, and food in the bag. Shield refused (second off-hand) and left in the bag, as `--equip` says.
- Load of that save and an immediate save (`r02-load-gear`): worn items, slots, wear and bag identical; only tick, stored time, digest and the sitting counter moved.
- Sack with items in its extra slots (`r05-bag-extra-held`): book moved into slot 35 (an extra slot of the sack), then picked up again and held at save time. The held book returned to slot 35 before the save; 40 slots saved.
- Load of that save, apple moved to the trash, save (`r06-load-extra-trash`): slot 35 book, bread and wood kept; the trashed apple is gone and the trash is empty after the load (as saves.md says).
- Shift-click of the worn sack back to the bag while its extra slot holds the book (`r10-bag-cannot-come-off`): refused, sack still worn, book still in slot 35, same digest as `r05`.
- Felt temperature in rain at 1 o'clock (`--time 1 --weather rain`): `r07-temp-half` (felt -29000000 after 20 s), a load and 20 s more (`r08-temp-loaded`, felt unchanged, same as the unbroken run), and an unbroken run to the same length (`r09-temp-unbroken`, felt -29000000 in both). Ticks differ by the load's own frames (2458 against 2429), so the digests are not expected to match; the felt values do.
- Hand-edited saves, eleven loads (`e-*`, from the gear save): unknown worn item (`dragon-helm`), wear 999 on the hat, a coat put into the off-hand, version 10, the inventory cut to 30 slots, no `worn` key, no `systems.temperature`, an inventory slot with no `count`, wear 50 on wood, a worn hat moved to the back slot, and the wear keys removed.
- Digest, wear and clamp results are read from the saves the loads wrote, with python (`-I`).
- No CLI `eval` or speech checks (not this area).

Not run, see "Not covered": F6 in a window, `--needs on` in a save, the quit save, a bag with items in the bag when a bag is taken off after a load.

## Bugs

### QA-2026-11-19-save-1 (minor, game)
- Reproduce: take the gear save (`qa-save/r01-gear/game.save`), replace the worn armour head `helmet` with `dragon-helm` (no such item in `game/items.json`), then `--load <that file> --screenshot <png> --frames 5 --save <file>`. The same happens with an inventory slot that has no `count` key.
- Expected: `docs/game/saves.md` says a worn item the data lacks "loads as nothing" (`WornSave.ToStacks`), so the game loads with that slot empty, or refuses with a message that names the item.
- Actual: the load is refused with `The restored world does not match the save's digest: the save is damaged or was made by another build (the restored digest is ..., the save says ...)`. The message says the save is damaged, not which item is unknown. The exit code is 1.
- Evidence: `qa-save/e-unknown-item/stderr.txt`, `qa-save/e-missing-count/stderr.txt`; the edit scripts are `qa-save/edits/make.py`.
- Likely file: `src/Vocaterra.Game.Core/Save/SaveGame.cs` (the digest check, about line 296; `RestoreParts`, about line 374), `src/Vocaterra.Game.Core/Save/WornSave.cs` (`ToStacks`), `src/Vocaterra.Game.Core/Save/SaveDocument.cs` (`SlotSave.ToStack`).
- Note: a real content change goes through `SaveMigration`, which reports the dropped items; this refusal only hits a same-bundle save that was hand-edited or damaged.

## Observations
- The inventory-size refusal reads `The save does not restore: The inventory has 30 slots, not the 40 its worn items give. (Parameter 'state')`. It is correct and refuses cleanly, but the text is a .NET parameter name and a technical line, not a sentence a player or a tester would act on. Seen with a 30-slot list under a worn sack (`e-bag-short`), a missing `worn` key with 40 slots (`e-no-worn`), and a hat in the back slot (`e-hat-in-back`).
- A worn item is not checked against its slot's group on load. `WornSave.ToStacks` only checks that the slot and item exist, so a coat in the off-hand loads into it. In the test the save was then refused only by the digest, because the lantern had been removed to make room; the fit check is therefore not proved either way (see Not covered).
- A load advances the stored time by about one second and raises `sitting` by one (1 to 2 in `r02`). This is expected by the save's design (`sitting` counts sittings), but a tester comparing two saves will see it.
- The trash is not saved: an apple trashed before the save is gone after the load (`r06`). saves.md and inventory-plan 3.x say the trash keeps its last item and the save does not write it, so this follows the design. A player who put a stack in the bin and then saved may still expect it back.
- Equipment that displaces a starting garment puts the garment in the bag (the starting shirt in `r01`, slot 1). That is correct; a tester may be surprised to find a second shirt in the bag.
- The digest and the tick of a loaded run differ from the unbroken run by the load run's own frames. The felt temperature matched exactly (`r08` and `r09`), so the continuation holds for that value; the exact digest comparison needs a run with no extra frames, as the save tests do.
