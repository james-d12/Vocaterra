# QA report: language (village series, sessions 4 to 10), 2026-11-01

Branch `feature/village-followups`, commit `9dfa08b`. Area `language`, narrowed to the village NPCs and lessons (sessions 7 to 10 in depth,
4 to 6 by the handover's line files). Covered:

- Build once (`dotnet build Vocaterra.sln -warnaserror -m:4` through `scripts/limited.sh`): passed, exit 0.
- Core CLI `eval` (through the wrapper `/tmp/vocaterra-qa/qa-batch.sh`, run under `scripts/limited.sh`): 120 handover lines
  (`/tmp/claude-1000/review/lines1.txt`, `lines2.txt`, `lines3.txt`) plus 151 new variants for the session 7 to 10 NPCs and lessons
  (`/tmp/vocaterra-qa/v-lines.txt`) plus 97 more (`/tmp/vocaterra-qa/v2-lines.txt`), and 36 targeted lines (`v3-lines.txt`). Results:
  `/tmp/vocaterra-qa/batch-all.out`, `v-out.txt`, `v2-out.txt`, `v3-out.txt`.
- Host transcript path (the game's typed path, `Vocaterra.Host --transcript --prompt`, wrappers `/tmp/vocaterra-qa/qa-host.sh` and
  `qa-host2.sh`): 39 lines, the suspicious ones from the CLI (`host-out.txt` to `host-out4.txt`).
- Game runs (`Vocaterra.Game`, `--mute`, one at a time): `--skip-to-session 8 --talk villager` with greeting-first lines (`/tmp/vocaterra-qa/gA`);
  `--skip-to-session 10` with `--talk farmer` and `--talk baker` (`/tmp/vocaterra-qa/gB`); the scripted runs `r22-market` (clean, passed:
  `/tmp/vocaterra-qa/scripted-r22/r22-market`) and `r23-future` (passed, exit 0; `/tmp/vocaterra-qa/scripted/r23-future`, see Not covered).
- Determinism: 384 distinct CLI inputs were checked; where a line was run more than once, the output was identical. The same host line gave the
  same result in `host-out.txt`, `host-out3.txt` and the game run `gA`.

The CLI and the host disagree on several lines (QA-language-1). QA-language-2 to 9 were confirmed on the host (and, where marked, in a game run),
not only on the CLI.

- Reproduce: `tools/Vocaterra.Nlp.Cli eval --transcript "hola, ¿dónde está el río?" --prompt villager-open --content content/game-v1`, and the same
  line through `src/Vocaterra.Host` with `--transcript "hola, ¿dónde está el río?" --prompt villager-open`.
- Expected: one verdict on both paths. The game path is the one a learner sees.
- Actual: CLI: `unknown`, `communicated=False`, no error. Host and game: `ask_directions`, communicated, "Mira, está allí." Other pairs:
  - `farmer-open` `hola, ¿cuánto es todo?`: CLI `greet` (vocab.wrong); host `ask_total`, "Quince manzanas, quince monedas."
  - `baker-open` `hola luz quiero dos panes por favor`: CLI `greet`; host `request_item`, "Aquí tienes el pan. ¡Gracias!"
  - `farmer-open` `puedo pagar con fruta y con pan`: CLI `unknown`, not communicated; host `ask_pay`.
  - `lesson-will-sell` `manana venderé fruta`: CLI `unknown` (communicated, vocab.unknown=mañana); host `state_action`, correctness 0.6.
  - `lesson-will-fetch` `mañana buscé madera para Luz`: CLI `unknown`; host `state_action`.
  - `lesson-mar-fished` `Mar pescé en el río`: CLI `unknown`; host `state_action` with the recast "¡Eso es! «Mar pescó en el río»."
  - Host and game agree with each other (the game run `gA` turn 1 and `host-out.txt`). The host with `--content content/game-v1` gives the
    same as without it (`host-out3.txt`), so the content folder is not the cause.
- Evidence: `/tmp/vocaterra-qa/v3-out.txt` (the CLI lines), `/tmp/vocaterra-qa/host-out.txt`, `host-out2.txt`, `host-out3.txt`;
  `/tmp/vocaterra-qa/gA/stdout.txt` lines 45 to 49 (the game: "turn 1 (villager, villager-open): "hola, ¿dónde está el río?" -> ask_directions, understood").
- Owner: core for the CLI verdict (`Vocaterra.Nlp` evaluation, its entry used by `tools/Vocaterra.Nlp.Cli`); game for the host's transcript
  path. The handover's measurements (section 9.3 B, C, D) were taken on the CLI, so they need to be re-measured on the host before a milestone
  is planned from them.
- Note: the greeting dead end I first saw on the CLI (`hola, ¿dónde está el río?` unknown, no error) is not in the game. Do not plan a fix to
  greetings from the CLI result alone.

### QA-language-2 (major, core: a correct learner name is rejected)
- Reproduce: `Vocaterra.Host --transcript "me llamo ana" --prompt farmer-open` (the same at `smith-open`, `me llamo luis`).
- Expected: a learner's own name in `me llamo …` is correct Spanish and is understood as `ask_name`.
- Actual: `intent=ask_name communicated=false correctness=0`, with `vocab.wrong` on `llamo` and `vocab.unknown` on `ana`. A known name also

- Evidence: `/tmp/vocaterra-qa/host-out4.txt` (the four lines); `batch-all.out` (CLI: `villager-open | me llamo ana => unknown comm=False vocab.unknown`).
- Owner: core (the name slot and the vocabulary check); the name list is game content (`content/game-v1`). The fix should accept any name as
  a name slot, not only the bundle's list. Likely: `src/Vocaterra.Nlp` name handling, `content/game-v1/lexicon`.

### QA-language-3 (major, core: a plural subject with a singular `costar` is praised)
- Reproduce: `scripts/limited.sh … Vocaterra.Game --skip-to-session 10 --talk farmer --say "las manzanas cuesta una moneda"` (also `--say "el pan" …`
  for the control).
- Expected: `cuestan` is needed with a plural subject before the verb (the error `conj.person=cuestan`, as `un pan cuestan dos monedas` already gets `conj.person=cuesta`).
- Actual: `ask_price`, `correctness 0.4`, one `vocab.wrong` on `manzanas` and no agreement tag. The NPC answers "Sí, «las manzanas cuesta una moneda». ¡Muy bien!" and
  then the model "Una manzana cuesta una moneda." The same for `los panes cuesta dos monedas` (CLI; not run on the host). The line is the session 10 `costar`
  lesson's error, so the learner is praised for it.
- Evidence: `/tmp/vocaterra-qa/gB/stdout.txt` lines 46 to 48 (turn 1, 40 %); `host-out2.txt`; CLI `v-out.txt` (`farmer-open | las manzanas cuesta una moneda`).
- Owner: core. Likely: the price agreement (M56) in `src/Vocaterra.Nlp.Es`. Adjacent to the handover's `los panes costa` (9.3 B), not the same
  slip: this one is a plural subject with a singular verb, and the case where the subject comes before the verb is missed.

### QA-language-6 (major, core and game: ungrammatical NPC recasts built from the wrong word)
- Reproduce: host `--transcript "compré three manzanas" --prompt lesson-market` and `--transcript "manana iré al río" --prompt lesson-will-go`.
- Expected: the recast repeats the learner's sentence corrected, and the error names the word that is wrong.
- Actual: "compré three manzanas" gives `vocab.unknown: expected 'compré', heard 'three'` (blames a correct word) and the recast "Sí, «compré compré manzanas». ¡Muy bien!".
  "manana iré al río" gives `vocab.unknown: expected 'al', heard 'manana'` and the recast "Claro, «al iré al río». Muy bien.". Both are ungrammatical Spanish from
  the NPC. The CLI gives `vocab.unknown=compré` and `vocab.unknown=al` for the same lines (`v2-out.txt`, `v3-out.txt`).
- Evidence: `/tmp/vocaterra-qa/host-out2.txt` (the two entries).
- Owner: core (the error's word choice in `src/Vocaterra.Nlp`, the recast assembly in the game's host text, likely `src/Vocaterra.Host` where the
  recast is built). Confirm which side builds the recast before planning the fix.

### QA-language-7 (major, core: the dropped `ñ` is a false alarm, and loses the intent on the CLI)
- Reproduce: game `--skip-to-session 10 --talk baker --say "manana compraré pan"` (run `gB`, turn 3); host `--transcript "manana compraré pan" --prompt lesson-will-buy`.
- Expected: `manana` is the accepted variant of `mañana` (the handover's "dropped accents" class), so nothing is flagged.
- Actual: `state_action`, correctness 0.6 (the game shows 60 %), `vocab.unknown: expected 'mañana', heard 'manana'`. The NPC says "¡Eso es! «Mañana compraré pan»."
  On the CLI, `manana venderé fruta` gives `unknown` with `communicated=True` (the intent is lost), while the host gives `state_action`.
  Accented `mañana` and an unaccented `ire` or `compre` pass clean, so only the `ñ` is the cause.
- Evidence: `/tmp/vocaterra-qa/gB/stdout.txt` line 64 to 66; `host-out2.txt`; `v3-out.txt`.
- Owner: core (the diacritic normalisation in `src/Vocaterra.Nlp`). If the owner decides `ñ` is a spelling error and not an accent, the
  feedback should still be "Mañana" in a recast and not a `vocab.unknown` tag.

### QA-language-8 (major, core: `cuanto son todo?` gets the wrong intent and a praise)
- Reproduce: host `--transcript "cuanto son todo?" --prompt farmer-open`.
- Expected: `ask_total` (the same question as `¿cuánto es todo?`), or "No te entendí" as for `¿cuánto son todo?`.
- Actual: `intent=describe`, communicated, correctness 1, and the NPC says "¡Bien!" The learner asks the price and gets praise and no
  answer. The accented `¿cuánto son todo?` gives `unknown` ("No te entendí"), which is the handover's 9.3 D(e), so the two forms disagree.
- Evidence: `/tmp/vocaterra-qa/host-out.txt` and `host-out2.txt` (the `cuanto son todo?` entry); CLI `v3-out.txt` (the same, `describe`).
- Owner: core, with the game's intent grammar (`content/game-v1/intents/intents.json`). Likely: the `describe` grammar takes the unaccented
  `cuanto son todo`, and `ask_total` does not. The handover's D(e) fix (`ask_total` takes `son`) covers only the `unknown` case.

### QA-language-9 (major, core: a wrong form the lexicon does not know is praised, and the NPC gives two contradictory replies)
- Reproduce: host `--transcript "buscé madera" --prompt lesson-will-fetch`; host `--transcript "Mar pescé en el río" --prompt lesson-mar-fished`.
- Expected: the unknown form `buscé` (for `busqué`) is an error, with one reply.
- Actual: `buscé madera`: `intent=unknown`, communicated, `vocab.unknown: expected 'buscaré', heard 'buscé'`, and the NPC says
  "Claro, «buscaré madera». Muy bien." and then "No te entendí. ¿Me lo dices otra vez?" in the same turn. `Mar pescé en el río`: correctness 0.6 with
  the recast "¡Eso es! «Mar pescó en el río»." (praise for a wrong form). The CLI gives `intent=unknown comm=True vocab.unknown=pescó`
  for `Mar pescé en el río` (`v-out.txt`). So an unrecognised conjugation is handled as an unknown word, not as a conjugation error.
- Evidence: `/tmp/vocaterra-qa/host-out2.txt`; `v-out.txt` (`lesson-mar-fished | Mar pescé en el río`).
- Owner: core (the conjugation check for a stem the lexicon does not produce, e.g. `pescar` and `buscar` preterite spelling changes); game
  (the reply should not praise and say "No te entendí" in one turn).
